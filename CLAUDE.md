# Работа над техническим заданием

## Что это за проект

Написание ТЗ на разработку по заполненному клиентом брифу.
Результат ложится в основу SDD-документации, по которой пишется код.

Ты не пишешь код. Ты не проектируешь БД. Ты пишешь требования.

## Роль

Загрузи и следуй системному промпту: `reference/prompt-tz-agent.md`.
Это твоя основная инструкция. Читай её в начале каждой сессии.

## Ключевые правила проекта

1. НИКОГДА не пиши в `00-input/` — там неприкосновенные данные клиента.
2. ВСЕГДА заполняй `01-tz/tz.md` по шаблону `reference/template-tz.md`.
   Нумерацию разделов не меняй: следующее звено ссылается на номера.
3. ВСЕГДА читай `01-tz/decisions.md` перед началом работы.
   Решение, записанное там, не перерешивается без нового основания.
4. ВСЕГДА читай разделы 4, 5, 6 файла `01-tz/tz.md` перед написанием
   любого другого раздела. Это язык документа.
5. НИКОГДА не выдумывай данные, которых нет в брифе. Пробел становится
   вопросом `Q-NNN` в разделе 16, а не догадкой.
6. ВСЕГДА помечай происхождение: `FR-CHK-012/Б` — из брифа,
   `FR-CHK-012/Р` — твоё решение. Требований без маркера не бывает.
7. НИКОГДА не сокращай формат требования. Полный формат — п. 4.3
   системного промпта: приоритет, очередь, роль, источник, требование,
   правила, критерии приёмки, связи.
8. ВСЕГДА запускай проверку после записи раздела:
   `python tools\check_tz.py 01-tz\tz.md`
   Ошибки уровня ERROR исправляй до конца сессии.
9. ВСЕГДА заканчивай сессию отчётом: сколько требований записано,
   их ID, какие пункты брифа остались непокрытыми, что решил сам и почему.
10. ВСЕГДА дописывай строку в `01-tz/session-log.md` в конце сессии.
    Колонки: Дата, Команда, Разделы, Записано, Новые Q, Что решил сам.
    В последней колонке — одной фразой каждое решение уровня `/Р`,
    каждый объединённый или снятый вопрос, каждая развилка, которую
    рассматривал. Эта колонка восстанавливает контекст сессии,
    если к ней придётся вернуться через месяц.
11. Одна сессия — один раздел или одна группа модулей. Не пытайся
    написать документ целиком: формат деградирует к концу.
12. Модуль `PRD` запрещён. Карточка товара — это `CARD`.
    `prd.md` в SDD называется так же, совпадение путает.
13. Матричные правила (оплата × доставка, права × роли) — одно
    бизнес-правило `BR-NNN` с таблицей, не набор отдельных требований.

## Структура проекта

```
00-input/        данные от клиента, только чтение
  brief.md         заполненный бриф
  answers.md       ответы клиента на вопросы
  attachments/     выгрузки, прайсы, скриншоты
01-tz/           рабочая папка
  tz.md            документ, растёт по разделам
  decisions.md     журнал решений
  coverage.md      карта заполнения
  session-log.md   журнал сессий
02-sdd/          следующий этап, пока пусто
reference/       эталоны, только чтение
tools/           валидатор
```

## Команды

```powershell
python tools\check_tz.py 01-tz\tz.md            # проверка
python tools\check_tz.py 01-tz\tz.md --strict   # с кодом возврата
git commit -am "tz: section 8.5 checkout, 12 requirements"
```

## Стиль ответов

Русский язык. Идентификаторы и коммиты — английский.
Плотно, без вводных фраз. Таблицы вместо перечислений.
Перед записью раздела — план: что войдёт, сколько требований ожидается.
