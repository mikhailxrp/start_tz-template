## Легенда маркировки

Каждое содержательное утверждение документа помечено источником.

| Маркер | Значение                             | Кто может изменить                      |
| ------ | ------------------------------------ | --------------------------------------- |
| `/Б`   | Из брифа. Клиент это сказал          | Только клиент, письменно                |
| `/Р`   | Решение аналитика. Клиент не говорил | Аналитик или архитектор, с обоснованием |

Идентификаторы: `FR-МОДУЛЬ-NNN/маркер` — функциональные требования, `NFR-КАТЕГОРИЯ-NNN/маркер` — нефункциональные, `BR-NNN/маркер` — бизнес-правила, `AS-NNN` — допущения, `Q-NNN` — открытые вопросы, `C-NNN` — разрешённые противоречия, `RISK-NNN` — риски.

Приоритет: `MUST` / `SHOULD` / `COULD` / `WON'T`. Очередь: `MVP` / `2` / `нет`.

```
### FR-CHK-012/Б · Пересчёт цен при оформлении

Приоритет: MUST | Очередь: MVP | Источник: бриф п. 4.1
Роль: Покупатель

Требование:
При переходе к оформлению заказа система пересчитывает стоимость
всех позиций корзины по текущим ценам каталога.

Правила:
1. Если цена позиции изменилась — показать уведомление с указанием
   старой и новой цены.
2. Если товар стал недоступен — пометить позицию и исключить из суммы.
3. Оформление заблокировано, пока покупатель не подтвердит изменения.

Критерии приёмки:
- Цена в базе изменена во время сессии → покупатель видит уведомление
  и не может оформить заказ по старой цене.
- Остаток обнулён во время сессии → позиция помечена, сумма пересчитана.

Связи: FR-CART-004, FR-STOCK-007
```

    ### FR-AI-001/Б · Разбор характеристик из текста описания

    Приоритет: MUST | Очередь: MVP | Источник: бриф п. 14.3
    Роль: Контент-менеджер
    Провайдер: обезличенные данные — любой
    Проверка результата: ревью Контент-менеджером до публикации
    При недоступности: задача откладывается в очередь, повтор через час

    Требование:
    Система извлекает значения характеристик из текстового описания
    Товара и раскладывает их по полям справочника характеристик Категории.

    Правила:
    1. Обрабатывается пакетом, не по одному Товару.
    2. Значение, не найденное в тексте, остаётся пустым — не выдумывается.
    3. Значение, не совпадающее ни с одним вариантом справочника,
       помечается как «требует решения», а не записывается как есть.
    4. Исходное описание не изменяется.

    Критерии приёмки:
    - Описание содержит «беззерновой, для стерилизованных» → соответствующие
      поля справочника заполнены, остальные пусты.
    - Описание не содержит данных о возрасте → поле «возраст» пустое,
      Товар не помечен как ошибочный.
    - Провайдер недоступен → задача в очереди, Контент-менеджер видит статус.

| С персональными данными | имя, телефон, состав заказа, адрес     | только российский         |

**Правила:**

1. Задача, в промпт которой попадают персональные данные, обрабатывается
   провайдером, размещённым в РФ.
2. Если класс задачи не определён явно — она считается содержащей ПДн.
3. Смена провайдера не требует изменения кода: выбор задаётся конфигурацией
   для каждого класса задач.
4. Данные покупателя не используются для обучения моделей провайдера —
   требование к договору.
