## С чего начать

1. Заполненный клиентом бриф → `00-input/brief.md`
2. Приложения (выгрузки, прайсы) → `00-input/attachments/`
3. Макеты дизайна, если есть → `00-input/design/`
4. Открыть папку в Claude Code: `claude`

---

## Команды по порядку

```
/tz-start          инвентаризация брифа, поиск дыр и противоречий
/tz-questions      письмо клиенту простым языком

       ↓ отправить, дождаться ответов
       ↓ положить ответы в 00-input/answers.md

/tz-answers        разбор ответов, обновление реестров
/tz-model          разделы 4-6: глоссарий, роли, состояния
/tz-scenarios      раздел 7: сценарии и ошибочные ветки
/tz-screens        реестр экранов — только если есть макеты

/tz-modules 8.0 8.1 8.2 8.3 8.18            главная, каталог, карточка, поиск, контент
/tz-modules 8.4 8.5 8.6 8.7                 корзина, оформление, оплата, доставка
/tz-modules 8.8 8.9 8.10 8.11               заказы, склад, возвраты, скидки
/tz-modules 8.12 8.13 8.14 8.15 8.16 8.17   кабинеты, админка, уведомления

/tz-ai             раздел 8.19: ИИ-помощники, если выбраны в брифе
/tz-rules          разделы 9-14: правила, интеграции, НФТ, приёмка
/tz-summary        разделы 1-3: резюме и границы

       ↓ закрыть Claude Code и открыть заново

/tz-review         ревью свежей сессией
```

Коммит после каждой команды:

```
git commit -am "tz: section 8.5 checkout, 12 requirements"
```

## Признаки, что процесс поехал

| Симптом | Что произошло | Действие |
|---|---|---|
| Требования к концу раздела короче | Дрейф формата | Вернуть к п. 4.3 промпта, переписать раздел |
| Доля маркеров `/Р` выше трети | Агент додумывает вместо вопросов | Проверить, задавались ли вопросы клиенту |
| Термины не из глоссария | Контекст потерян | Явно вставлять раздел 4 в начало сессии |
| В модуле меньше 5 требований | Молчаливое сокращение | Сверить с `coverage.md` |
| Требование пересказывает макет | Дублирование дизайна | Оставить только «поведение сверх макета» |
