# Реестр экранов

Заполняется командой `/tz-screens` из макетов в `00-input/design/`.
Требования раздела 8 ссылаются на экраны по `ID`, а не по имени файла.

**Источник:** `00-input/design/`
**Режим:** [скриншоты / Figma / вёрстка / смешанный] ← определяется командой
**Состояние дизайна:** ← бриф п. 11.1

## Факты, извлечённые из вёрстки

`[УДАЛИТЬ РАЗДЕЛ ЕСЛИ РЕЖИМ НЕ «ВЁРСТКА» И НЕ «СМЕШАННЫЙ»]`

Только для экранов, где макет — HTML-код: списки полей форм, вариантов
доставки/оплаты, опций выбора, извлечённые из разметки. Каждый факт
помечен как требующий подтверждения — макет мог нарисовать демонстрационный
набор, а не финальный.

```
### SCR-NN · Название экрана (имя-файла.html)

**Что извлечено:** (поля формы / варианты выбора / радиокнопки и т.п.)
- ...

⚠ Требует подтверждения клиентом — источник: демонстрационная вёрстка.
```

## Недостающие состояния

Дизайнер рисует счастливый путь. Здесь — то, чего на макетах нет,
но что понадобится при реализации. Закрывает дизайнер, не аналитик.

Для режима «Вёрстка»: проверено, что состояния нет ни в одном файле
экрана (не только в основном) — прежде чем заносить сюда.
