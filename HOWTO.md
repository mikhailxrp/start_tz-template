# Как пользоваться шаблоном ТЗ

## Что мы построили

Представь фабрику по производству документов. У фабрики три цеха:

```
Бриф  →  ТЗ  →  SDD-документы  →  Код
```

**Бриф** — анкета. Её заполняет клиент. Он отвечает на вопросы про свой магазин: чем торгует, как принимает оплату, кто такие менеджеры.

**ТЗ** — техническое задание. Его пишет Claude по анкете. Это перевод «хотелок клиента» на язык, понятный программисту.

**SDD** — план стройки. По нему уже пишется код.

Мы построили первый цех — тот, что делает ТЗ из брифа. И построили его так, чтобы он работал не один раз, а для каждого нового клиента.

---

## Что лежит в папках

```
D:\Development\tz-template\      ← это ЭТАЛОН, отсюда всё копируется
```

| Что | Зачем |
|---|---|
| `CLAUDE.md` | Правила для Claude. Он читает их каждый раз |
| `reference\` | Образцы: анкета для клиента, форма ТЗ, инструкции для Claude |
| `tools\check_tz.py` | Проверяльщик. Ищет ошибки в готовом ТЗ |
| `tools\new-project.ps1` | Создаёт папку под нового клиента |
| `.claude\commands\` | Кнопки-команды, которые Claude понимает |
| `template\` | Пустая заготовка проекта |

**Главное правило:** в `tz-template` ты не работаешь. Это склад образцов. Работа идёт в папках клиентов.

---

## Начало работы с новым клиентом

### Шаг 1. Отправить клиенту анкету

Возьми файл:

```
D:\Development\tz-template\reference\brief-ecommerce.md
```

Отправь клиенту. Пусть заполнит. Он не программист — вопросы написаны понятным языком.

Попроси приложить выгрузку 20–30 товаров в Excel. Это заменит десяток уточняющих вопросов.

### Шаг 2. Создать папку проекта

Открой PowerShell:

```powershell
cd D:\Development\tz-template
.\tools\new-project.ps1 -Name "имя-клиента"
```

Появится папка `D:\Development\имя-клиента` со всем необходимым внутри.

Имя пиши латиницей, без пробелов: `acme-shop`, `mebel-plus`.

### Шаг 3. Положить бриф в проект

Заполненную клиентом анкету положи сюда:

```
D:\Development\имя-клиента\00-input\brief.md
```

Файл должен называться именно `brief.md`.

Приложения от клиента (Excel, скриншоты, прайсы) — в папку рядом:

```
D:\Development\имя-клиента\00-input\attachments\
```

### Шаг 4. Открыть Claude Code

```powershell
cd D:\Development\имя-клиента
claude
```

Всё. Дальше — команды.

## Команды по порядку

Их девять. Запускай строго по очереди, не перепрыгивая.

### 1. `/tz-start`

Claude читает анкету и говорит, чего в ней не хватает.

**Что получишь:** список вопросов к клиенту.

**Что делать дальше:** отправить вопросы клиенту, дождаться ответов, дописать их в `brief.md`.

Не пропускай этот шаг. Он самый важный: тут ловятся дыры, которые потом стоят недель работы.

---

### 2. `/tz-model`

Claude пишет «словарь» проекта: что такое товар, что такое заказ, какие бывают роли, какие статусы у заказа.

**Что получишь:** разделы 4, 5, 6 в файле `01-tz\tz.md`.

**Что проверить:** открой файл, прочитай раздел 4 (Глоссарий). Если термины кажутся тебе странными — скажи Claude, он поправит. На этом языке будет написан весь остальной документ.

---

### 3. `/tz-scenarios`

Claude описывает, что происходит, когда покупатель что-то делает. Включая ситуации «а если товар кончился прямо во время оплаты».

**Что получишь:** раздел 7.

---

### 4–7. `/tz-modules`

Самая долгая часть. Claude пишет сами требования — их будет 100–200 штук.

Запускай **четырьмя отдельными командами**, по одной за раз:

```
/tz-modules 8.1 8.2 8.3 8.18
/tz-modules 8.4 8.5 8.6 8.7
/tz-modules 8.8 8.9 8.10 8.11
/tz-modules 8.12 8.13 8.14 8.15 8.16 8.17
```

**Почему не все сразу:** если попросить всё разом, Claude устанет и начнёт писать короче и хуже. Порциями — качество ровное.

**После каждой команды** Claude сам запустит проверку. Если найдёт ошибки — исправит.

**Что делать тебе:** сохранить результат в историю:

```powershell
git add . ; git commit -m "tz: modules 8.1-8.3"
```

---

### 8. `/tz-rules`

Правила: как считается доставка, какие скидки складываются, что синхронизируется с 1С.

**Что получишь:** разделы 9–14.

---

### 9. `/tz-summary`

Короткое описание проекта для клиента. Пишется в самом конце — когда уже понятно, сколько всего получилось.

**Что получишь:** разделы 1–3.

---

### 10. `/tz-review`

**Важно: закрой Claude Code и открой заново.** Нужна «свежая голова».

```powershell
exit
claude
/tz-review
```

Claude прочитает готовый документ как чужой и найдёт ошибки.

**Почему новая сессия:** тот, кто писал, своих ошибок не видит. Ни человек, ни Claude.

## Проверка руками

В любой момент можешь проверить документ сам:

```powershell
python tools\check_tz.py 01-tz\tz.md
```

Что увидишь:

| Строка | Значение |
|---|---|
| `Требований найдено: 147` | Сколько написано |
| `из брифа: 120` | Столько сказал клиент |
| `решение аналитика: 27` | Столько придумал Claude |
| `Ошибок: 0` | Всё в порядке |
| `Ошибок: 5` | Надо чинить |

**Тревожный знак:** если «решение аналитика» больше трети — Claude слишком много додумал вместо того, чтобы спросить клиента.

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| Claude пишет требования всё короче | Скажи: «нарушено правило 7 из CLAUDE.md, перепиши раздел» |
| Появились новые непонятные термины | Скажи: «используй только термины из раздела 4» |
| В модуле всего 3 требования | Скажи: «сверь с coverage.md, проверь покрытие пунктов брифа» |
| Хочешь откатить последнюю сессию | `git checkout -- 01-tz\tz.md` |

## Что показать клиенту

Клиент не прочитает 100 страниц. Он прочитает четыре раздела. Покажи именно их:

| Раздел | О чём |
|---|---|
| 1 | Резюме проекта |
| 6.3 | Статусы заказа |
| 9 | Бизнес-правила: скидки, доставка, резерв |
| 14 | Как будем принимать работу |

Если клиент подтвердит эти четыре — остальное почти наверняка тоже верно.

## Как улучшать шаблон

Заметил, что Claude чего-то не учитывает? Правь **эталон**, не копию в проекте:

```powershell
cd D:\Development\tz-template
# правишь файл в reference\ или .claude\commands\
git add . ; git commit -m "prompt: добавил правило про X"
```

Следующий проект получит улучшение автоматически. Текущий — нет, и это правильно: менять правила посреди работы хуже, чем доработать по старым.
